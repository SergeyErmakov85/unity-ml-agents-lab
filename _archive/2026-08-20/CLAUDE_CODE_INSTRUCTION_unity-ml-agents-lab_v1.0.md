## 1. Миссия и итоговый результат

1.1. Превратить `unity-ml-agents-lab` в **воспроизводимую учебно-исследовательскую платформу**, в которой каждый метод обучения с подкреплением, описанный в уроках репозитория `cyber-unity-learn` (сайт `https://rl-cuber-unity-code.com/`), имеет **завершённый практический пример**.

| # | Компонент | Артефакт |
|---|---|---|
| 1 | Сцена Unity с ML-Agents-агентом | `unity/MLAgentsLab/Assets/Envs/E##_Name/` |
| 2 | Headless-сборка среды | `builds/E##_Name/` |
| 3 | Ноутбук обучения с авторской нейросетью и алгоритмом | `notebooks/E##_Name__<algo>.ipynb` |

1.3. **Ключевое инженерное требование.** Обучение выполняется **собственным кодом на PyTorch** (авторские сети, ручная настройка всех гиперпараметров, самостоятельно реализованные алгоритмы), а **не** через `mlagents-learn`. 1.4. **Критерий качества всей работы.** Пользователь, имеющий только чистый клон `unity-ml-agents-lab`, Unity Hub и Python, воспроизводит любой пример от нуля до обученного ONNX-агента в Unity, следуя `README.md`, без обращения к автору.

## 8. Стандарт Python-ядра (`labrl`)

8.1. **Подключение к среде.** Обёртка `labrl.envs.unity_env` **MUST** поддерживать два режима:
- **Editor-режим** (`file_name=None`) — отладка: пользователь нажимает Play в Unity;
- **Build-режим** (`file_name=builds/...`) — обучение: `no_graphics=True`, `time_scale` через `EngineConfigurationChannel`.

8.2. **MUST.** `VecUnityEnv`: N одинаковых `TrainingArea` внутри одного билда трактуются как N параллельных сред. Обёртка возвращает батч наблюдений формы `(N, obs_dim)` и корректно обрабатывает рассинхронизацию `DecisionSteps` / `TerminalSteps` (агент, завершивший эпизод, не смешивается с продолжающими).

8.3. **MUST.** Гарантии API обёртки: `reset() -> obs`, `step(actions) -> (obs, reward, terminated, truncated, info)`. Различие `terminated` (истинное завершение) и `truncated` (обрыв по `MaxStep`) обязательно — бутстрэппинг значения при `truncated` выполняется, при `terminated` не выполняется. Ошибка в этом месте искажает обучение и **MUST** быть покрыта тестом.

8.4. **Авторские сети.** `labrl.nets.protocols` **MUST** определять минимальные протоколы (`QNetwork`, `PolicyNetwork`, `ValueNetwork`) с явно документированными формами входов и выходов. Пользователь передаёт **любой** свой `nn.Module`, удовлетворяющий протоколу, в конструктор алгоритма. Жёсткая привязка алгоритма к конкретной архитектуре **MUST NOT** допускаться.

8.5. **Алгоритмы.** Каждый алгоритм — самостоятельный файл, реализованный «с нуля» на PyTorch, без сторонних RL-библиотек (`stable-baselines3`, `rllib` и аналоги **MUST NOT** использоваться в учебном коде). Обязательная структура модуля:

```python
@dataclass
class DQNConfig:            # ВСЕ гиперпараметры, значения по умолчанию, единицы измерения в комментариях
    ...

class DQN:
    def __init__(self, q_net, target_net, cfg, logger): ...
    def act(self, obs, epsilon) -> np.ndarray: ...
    def update(self, batch) -> dict[str, float]:   # <- единственное место обновления параметров
        ...
    def state_dict(self) / load_state_dict(...)
    def policy_module(self) -> nn.Module:          # <- модуль, экспортируемый в ONNX
```

8.6. **MUST.** Всё, что влияет на результат, задаётся в конфиге; «магические числа» внутри функций **MUST NOT** присутствовать.

8.7. **MUST.** Единственная точка обновления параметров — метод `update()`. Дублирование логики алгоритма между пакетом и ноутбуком **запрещено** (см. 9.4).

## 10. Контракт экспорта ONNX (критический раздел)

10.1. **Проблема.** Модель, экспортированная «обычным» `torch.onnx.export`, **не будет принята** Unity Inference Engine: ML-Agents требует строго определённых имён входов, имён выходов и служебных выходов-констант. Ошибка здесь ломает весь замысел проекта.

10.2. **MUST.** Контракт **извлекается из установленного пакета**, а не из памяти модели. Обязательные действия:

1. Найти пакет: `python -c "import mlagents, os; print(os.path.dirname(mlagents.__file__))"`.
2. Прочитать `mlagents/trainers/model_serialization.py` (класс-обёртка экспорта, списки `input_names`, `output_names`, `dynamic_axes`, константа opset).
3. Прочитать `mlagents/trainers/torch/model_serialization.py` и `mlagents/trainers/policy/torch_policy.py` (порядок наблюдений, формирование масок, версия API модели).
4. Зафиксировать в `docs/04_ONNX_CONTRACT.md`: точные имена, порядок, формы, значения констант, версия opset, версия пакета, пути к прочитанным файлам.

10.3. **Ожидаемая форма контракта (подлежит подтверждению по 10.2).**

- **Входы:** `obs_0`, `obs_1`, … — по одному на сенсор, в порядке регистрации сенсоров в Unity; `action_masks` — для дискретных действий; `memory_in` — только для рекуррентных политик.
- **Выходы-значения:** `continuous_actions` и/или `discrete_actions`; `deterministic_continuous_actions` и/или `deterministic_discrete_actions`; `memory_out` — для рекуррентных.
- **Выходы-константы:** `version_number` (версия API модели), `memory_size`, `continuous_action_output_shape` и/или `discrete_action_output_shape` (размер непрерывного вектора / список размеров дискретных ветвей).
- **opset:** значение берётся из константы пакета `mlagents`, а не выбирается произвольно.

10.4. **MUST.** Экспорт выполняется через обёртку `labrl.export.onnx_export.MLAgentsPolicyWrapper(nn.Module)`, которая:
- принимает обученный модуль политики;
- возвращает из `forward` полный набор выходов контракта, включая константы (зарегистрированные как буферы);
- для дискретных действий возвращает **индексы выбранных действий** формы `(batch, num_branches)`, а не логиты;
- для непрерывных — действия в диапазоне, соответствующем `ActionSpec` среды;
- задаёт `dynamic_axes` по батчу.

10.5. **MUST.** Автоматическая верификация `labrl.export.onnx_verify` выполняется сразу после экспорта и **блокирует** приёмку при провале:

| Проверка | Критерий |
|---|---|
| Структура | `onnx.checker.check_model` без ошибок |
| Имена | Множества входов и выходов **точно** совпадают с контрактом из `docs/04_ONNX_CONTRACT.md` |
| Константы | `version_number`, `*_output_shape`, `memory_size` равны ожидаемым значениям |
| Формы | Прогон `onnxruntime` на батче 1 и 64 без ошибок |
| Числовой паритет | max‖ONNX − PyTorch‖∞ ≤ 1e-4 на 64 случайных наблюдениях из реального распределения среды |
| Диапазоны | Непрерывные действия внутри допустимого диапазона; дискретные — целые в `[0, branch_size)` |

10.6. **MUST.** Проверка «в бою»: модель кладётся в `Assets/Envs/E##_<Name>/Models/`, назначается в `BehaviorParameters.Model`, `Behavior Type = Inference Only`; выполняется прогон **20 эпизодов**. Критерий приёмки: средняя награда в Unity **≥ 0.8 ×** средней награды при оценке в Python. Отклонение ниже порога **MUST** расследоваться (типовые причины: рассогласование порядка наблюдений, отсутствующая нормализация, различие в частоте принятия решений) и фиксироваться в `docs/07_TROUBLESHOOTING.md`.

10.7. **MUST.** Нормализация наблюдений, если она применяется в Python, **MUST** быть либо встроена в экспортируемый граф, либо отключена. Хранение статистик нормализации вне ONNX **запрещено** — это гарантированный источник расхождения Python и Unity.
