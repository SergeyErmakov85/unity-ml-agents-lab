# reinforce — REINFORCE (Monte-Carlo policy gradient) с baseline

**Урок:** 2.1 «Policy Gradient», `https://rl-cuber-unity-code.com/courses/2-1`
**Реализация:** `python/labrl/algos/reinforce.py`
**Класс:** `REINFORCE` / конфиг: `ReinforceConfig`
**Семейство:** policy gradient, on-policy, Monte-Carlo (без бутстрэпа)
**Применим к:** действия непрерывные, дискретные и **гибридные**; наблюдения векторные и сеточные

## Идея в двух предложениях

REINFORCE берёт полный эпизод, считает для каждого шага фактический возврат
$G_t$ и сдвигает параметры так, чтобы действия с большим возвратом стали
вероятнее. Ни критика в цели, ни бутстрэпа, ни целевых сетей — только
логарифм правдоподобия действия, умноженный на то, чем эпизод кончился.

## Место в линейке методов

Это **первый** метод лаборатории, который обучает политику напрямую.
Табличный Q-learning и DQN учили ценность и выводили политику из неё
($\arg\max_a Q$); здесь параметры политики двигаются градиентом целевой
функции $J(\theta)$ самой политики. Разница принципиальна: политика может
быть стохастической и непрерывной, а жадный максимум по непрерывному
действию считать не нужно.

От REINFORCE до A2C (`docs/algos/a2c.md`) ровно один шаг: заменить
Monte-Carlo возврат $G_t$ на бутстрэп-оценку $r_t + \gamma V(s_{t+1})$.

## Математика

Теорема о градиенте политики:

$$
\nabla_\theta J(\theta) = \mathbb{E}_{\pi_\theta}\Bigl[\sum_t \nabla_\theta
\log \pi_\theta(a_t|s_t)\,G_t\Bigr], \qquad
G_t = \sum_{k \ge t} \gamma^{k-t} r_k
$$

С baseline $b(s)$:

$$
\nabla_\theta J(\theta) = \mathbb{E}_{\pi_\theta}\Bigl[\sum_t \nabla_\theta
\log \pi_\theta(a_t|s_t)\,\bigl(G_t - b(s_t)\bigr)\Bigr]
$$

Функция потерь (минимизируется):

$$
\mathcal{L}(\theta, \phi) = -\mathbb{E}\bigl[\log \pi_\theta(a_t|s_t)\,\hat A_t\bigr]
+ c_v\,\mathbb{E}\bigl[(V_\phi(s_t) - G_t)^2\bigr]
- c_H\,H(\pi_\theta),
\qquad \hat A_t = G_t - V_\phi(s_t)
$$

- $\theta$ — параметры политики, $\phi$ — параметры baseline;
- $\gamma$ — дисконт; $c_v$ — `value_coef`, $c_H$ — `entropy_coef`;
- $\hat A_t$ дополнительно нормируется по батчу при `normalize_advantage`;
- $V_\phi$ входит в цель **только вычитанием** и отсоединён от графа
  (`values.detach()`): baseline снижает дисперсию, а не задаёт направление.

### Почему baseline не портит оценку

$\mathbb{E}_{a \sim \pi}[\nabla_\theta \log \pi_\theta(a|s)\,b(s)]
= b(s)\,\nabla_\theta \sum_a \pi_\theta(a|s) = b(s)\,\nabla_\theta 1 = 0$.
Вычитание любой функции **состояния** оставляет градиент несмещённым, но
уменьшает разброс: без него множитель $G_t$ содержит всё, что произошло
после шага $t$, включая никак с ним не связанное.

Флаг `baseline: false` в конфиге даёт «чистый» REINFORCE урока 2.1 — он
работает, но на `E05` разброс возвратов между эпизодами таков, что метод
почти не двигается с места.

### Гибридное действие

Непрерывная и дискретная части независимы, поэтому логарифмы складываются:

$$
\log \pi(a|s) = \log \pi_{\text{непр}}(a_c|s) + \sum_{b} \log \pi_{\text{дискр}}^{(b)}(a_d^{(b)}|s)
$$

Ни одна строка самого REINFORCE от этого не меняется — меняется только
политика (`labrl.nets.hybrid_policy.GridHybridPolicy`).

### Обрыв по времени — не провал

Возврат для эпизода, оборванного по `MaxStep`, считается с бутстрэпом:
`discounted_returns(..., bootstrap=V(s_T))`. Без этого метод выучил бы, что
конец отсчёта времени равносилен провалу, — та же ошибка `terminated` против
`truncated`, что и в GAE (требование 8.3).

## Что именно обновляется

Единственная точка обновления параметров — метод `update()` (требование 8.7).
В ноутбуке его исходник печатается ячейкой 6:

```python
import inspect
from labrl.algos.reinforce import REINFORCE
print(inspect.getsource(REINFORCE.update))
```

**Один** шаг градиента по всем накопленным эпизодам, после чего данные
выбрасываются: они описывали политику, которой больше нет. Обновление
запускается, когда собрано `episodes_per_update` **завершённых** эпизодов —
не по числу шагов, как у A2C и PPO.

## Гиперпараметры

| Параметр | Значение по умолчанию | Единицы | На что влияет |
|---|---|---|---|
| `gamma` | 0.99 | — | горизонт дисконтирования |
| `learning_rate` | 3e-4 | — | шаг Adam, общий для политики и baseline |
| `value_coef` | 0.5 | — | вес ошибки baseline; 0 — baseline не обучается |
| `entropy_coef` | 0.01 | — | бонус за энтропию |
| `max_grad_norm` | 0.5 | — | клиппинг нормы градиента; 0 — не клипировать |
| `normalize_advantage` | true | — | нормировка $\hat A$ по батчу |
| `episodes_per_update` | 16 (конфиг среды) | эпизодов | размер одного обновления |

Энтропийный бонус здесь выше, чем у PPO (0.01 против 0.005), намеренно:
у REINFORCE нет обрезки шага, и рано схлопнувшаяся политика не восстановится —
данные для следующего обновления собирает она же.

Все параметры живут в `ReinforceConfig`; «магических чисел» внутри методов
нет (требование 8.6).

## Требования к сети

Политика передаётся пользователем и обязана уметь:

- `forward(*obs) -> (mean, logits)` — среднее непрерывной части `(B, A_c)`
  и склеенные логиты дискретных веток `(B, Σ branches)`;
- `log_prob(*obs, continuous, discrete) -> (B,)`;
- `entropy(*obs) -> ()`;
- `split_logits(logits)`, `clamped_log_std()`, свойства `continuous_dim`,
  `discrete_branches`.

Baseline — любой модуль `(*obs) -> (B, 1)`; `None` отключает его. Жёсткой
привязки к архитектуре нет (требование 8.4): `GridHybridPolicy` — реализация
по умолчанию, а не условие работы алгоритма.

## Метрики в TensorBoard

Обязательные теги раздела 11.2 плюс:

| Тег | Что показывает | Что означает нездоровый график |
|---|---|---|
| `Custom/Return Mean` | средний возврат $G_t$ в батче | не растёт при растущей `Env/SuccessRate` — расходятся цель и приёмка |
| `Custom/Return Std` | разброс возвратов | падение почти в ноль — политика схлопнулась, разведки нет |
| `Custom/Log Std` | ширина гауссовой части | быстрый уход ниже −2 в начале обучения — поднять `entropy_coef` |
| `Custom/Grad Norm` | норма градиента до клиппинга | устойчиво упирается в `max_grad_norm` — уменьшить шаг |
| `Custom/Episodes Pending` | эпизодов накоплено к обновлению | стабильно 0 — эпизоды не завершаются, обновлений не будет |

## Типичные отказы и как их распознать

| Симптом на графиках | Вероятная причина | Что проверить |
|---|---|---|
| награда стоит, `Custom/Return Std` огромен | дисперсия Monte-Carlo | включить `baseline: true`, поднять `episodes_per_update` |
| `Policy/Entropy` падает в первые же обновления | шаг слишком велик либо `entropy_coef` мал | уменьшить `learning_rate`, поднять энтропийный бонус |
| обновлений почти нет при растущем числе шагов | эпизод длинный, а `episodes_per_update` велик | считать: 300 решений × 16 эпизодов / 8 арен = 600 шагов сбора на обновление |
| награда растёт, а в Unity агент другой | непрерывное действие не приведено к диапазону Unity | `to_env_action` в пути сбора (T-12) |
| политика хороша к середине и разваливается к концу | нет затухания шага | `learning_rate: linear` до нуля (T-13) |

## Экспорт в ONNX

Стратегия для `MLAgentsPolicyWrapper`: **гибридная** — непрерывная часть
приводится к диапазону Unity преобразованием $\mathrm{clamp}(x, -3, 3)/3$,
дискретная выходит **индексом** ветки (`argmax` логитов), а не one-hot
(`docs/04_ONNX_CONTRACT.md`, §4.3). Экспортируется только политика:
baseline существовал ради снижения дисперсии при обучении и в Unity не нужен.

`REINFORCE.deterministic_action` вычисляет ровно то же, что граф
(`deterministic_continuous_actions` / `deterministic_discrete_actions`),
поэтому Python-оценка и поведение в Unity сравнимы напрямую — на этом
и держится проверка 10.6.
