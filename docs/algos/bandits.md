# bandits — многорукие бандиты: ε-greedy, UCB1, Thompson Sampling

**Урок:** 1.7 «Exploration vs Exploitation», `https://rl-cuber-unity-code.com/courses/1-7`
**Реализация:** `python/labrl/algos/bandits.py`
**Класс:** `Bandit` / конфиг: `BanditConfig`
**Семейство:** табличный, без состояний (MDP с единственным состоянием)
**Применим к:** действия дискретные (одна ветка), наблюдения — константа либо контекст

## Идея в двух предложениях

Бандит оценивает среднюю награду каждого действия выборочным средним и
выбирает действие по одному из трёх правил. Никакой динамики, никакого
следующего состояния: единственный вопрос метода — как делить конечный бюджет
попыток между проверкой неизвестного и использованием лучшего известного.

## Математика

Общая часть у всех трёх стратегий — инкрементальная оценка ценности руки:

$$
Q_k \leftarrow Q_k + \frac{1}{N_k}\bigl(r - Q_k\bigr)
$$

где $N_k$ — число нажатий руки $k$ после текущего. Шаг $1/N_k$ — не эвристика:
он в точности даёт несмещённое выборочное среднее $Q_k = S_k / N_k$, и хранить
историю наград не требуется.

Различаются стратегии **только** правилом выбора.

**ε-greedy:**

$$
a = \begin{cases}
\text{случайная рука}, & \text{с вероятностью } \varepsilon\\
\arg\max_k Q_k, & \text{иначе}
\end{cases}
$$

**UCB1** (Auer, Cesa-Bianchi, Fischer, 2002):

$$
a = \arg\max_k \left( Q_k + c\,\sqrt{\frac{\ln t}{N_k}} \right),
\qquad N_k = 0 \Rightarrow \text{приоритет } +\infty
$$

$t$ — общее число нажатий. Второе слагаемое — ширина доверительного интервала:
велика для редко испробованных рук, стягивается по мере накопления данных.

**Thompson Sampling** (Thompson, 1933), для бернуллиевских наград:

$$
\theta_k \sim \mathrm{Beta}\bigl(\alpha_0 + S_k,\; \beta_0 + N_k - S_k\bigr),
\qquad a = \arg\max_k \theta_k
$$

$S_k$ — число наград, равных 1. Beta — сопряжённое априорное к Бернулли,
поэтому апостериорное считается **точно**, без приближений.

Обозначения: $Q_k$ — оценка средней награды руки, $N_k$ — счётчик нажатий,
$c$ — коэффициент оптимизма UCB (классическое значение $\sqrt{2}$),
$\alpha_0, \beta_0$ — параметры априорного Beta.

## Что именно обновляется

Единственная точка обновления — метод `update()` (требование 8.7).
В ноутбуке его исходник печатается ячейкой 6:

```python
import inspect
from labrl.algos.bandits import Bandit
print(inspect.getsource(Bandit.update))
```

Обновление внутри батча **последовательное**, а не векторное: если две арены
нажали одну руку на одном шаге, второй исход обязан уточнять уже уточнённую
оценку. Векторизация применила бы оба к исходному $Q_k$ и дала бы неверное
среднее.

## Гиперпараметры

| Параметр | Значение по умолчанию | Единицы | На что влияет |
|---|---|---|---|
| `strategy` | `eps_greedy` | — | правило выбора: `eps_greedy` / `ucb` / `thompson` |
| `ucb_c` | 1.414 | — | ширина разведки UCB; больше — дольше сходимость |
| `prior_alpha` | 1.0 | — | α₀ Beta-априорного; (1, 1) = «ничего не известно» |
| `prior_beta` | 1.0 | — | β₀ Beta-априорного |
| `initial_value` | 0.0 | награда | оптимистичная инициализация: > 0 стимулирует разведку сама по себе |

Расписание ε задаётся снаружи (`labrl.utils.schedules`) и используется
**только** стратегией `eps_greedy`.

## Требования к сети

Сети нет. Состояние алгоритма — три вектора длины `num_actions`: оценки,
счётчики нажатий и счётчики успехов.

## Метрики в TensorBoard

Обязательные теги раздела 11.2 плюс специфичные для метода:

| Тег | Что показывает | Что означает нездоровый график |
|---|---|---|
| `Losses/Value Loss` | средняя ошибка предсказания \|r − Q(a)\| | не убывает — оценки не сходятся |
| `Policy/Learning Rate` | средний шаг 1/N | не убывает — разведка не концентрируется |
| `Policy/Entropy` | энтропия скользящего распределения выборов | остаётся на log K — метод не эксплуатирует |
| `Custom/Regret Per Pull` | сожаление на нажатие (нужны истинные вероятности) | не убывает — разведка неэффективна |
| `Custom/Q Max` | оценка лучшей руки | сильно выше истинного максимума — переоценка от малой выборки |
| `Env/Regret` | сожаление, посчитанное самой средой | то же, но независимо от Python |

Про `Policy/Epsilon`: тег пишется всегда, но для `ucb` и `thompson` он равен
нулю — у этих стратегий нет параметра разведки. Состав обязательных тегов
не должен зависеть от метода, иначе графики не лягут на одну ось.

## Типичные отказы и как их распознать

| Симптом на графиках | Вероятная причина | Что проверить |
|---|---|---|
| `Eval/Mean Reward` застряла на значении второй руки | ε упало раньше, чем накопились данные | растянуть `decay_steps`; для UCB — поднять `ucb_c` |
| Все руки нажаты примерно поровну до конца | ε не убывает либо `ucb_c` слишком велик | расписание ε; `ucb_c` порядка √2 |
| Оценка колеблется при неизменных счётчиках | это шум оценки, а не метода | увеличить `eval.episodes`: при p = 0.8 и 200 нажатиях σ ≈ 0.03 |
| Модель в Unity всегда выбирает руку 0 | наблюдение не равно 1.0 | `E00_Bandit` обязан отдавать константу 1.0 (см. ENV_SPEC, §4) |

## Экспорт в ONNX

Стратегия для `MLAgentsPolicyWrapper`: `greedy`.

Вектор оценок формы (1, K) экспортируется линейным слоем без смещения:
наблюдение среды — константа 1.0, то есть корректный one-hot вектор
единственного состояния, и `onehot(s) @ Qᵀ == Q[s]`. Вся разведка (ε, бонус
UCB, розыгрыш апостериорного) живёт на стороне Python и в граф не входит —
в Unity уезжает та политика, которую оценивали, то есть жадная.
