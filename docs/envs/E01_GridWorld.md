# E01_GridWorld

**Урок:** уроки 1.3–1.4 курса `cyber-unity-learn` (`https://rl-cuber-unity-code.com/`)
**Задача:** дойти из левой нижней клетки 5×5-сетки в правую верхнюю, обойдя стены и не попав в ловушки.
**Тип MDP:** дискретный, эпизодический, наблюдаемость полная, динамика детерминированная.
**Статус:** DONE (2026-08-15)
**Спецификация:** `unity/MLAgentsLab/Assets/Envs/E01_GridWorld/ENV_SPEC.md` (TS-001, ред. 1.1)

## Пространство наблюдений

| Индекс | Источник | Тип | Размерность | Нормализация |
|---|---|---|---|---|
| 0 | `VectorSensor` | float | 25 | не нужна: one-hot уже в [0, 1] |

`obs_size` = 25. Наблюдение — one-hot индекса клетки `s = r·5 + c`.

Такое представление выбрано не случайно: оно делает среду пригодной **и** для
табличных методов (индекс состояния берётся как `argmax`), **и** для
нейросетевых (one-hot — обычный вход). Оно же позволяет экспортировать таблицу
Q в ONNX без потери точности (см. раздел «ONNX»).

## Пространство действий

| Тип | Ветви | Семантика | Диапазон |
|---|---|---|---|
| Discrete | 1 ветвь × 4 | 0 = N (+r), 1 = S (−r), 2 = E (+c), 3 = W (−c) | целые [0, 4) |

Ход в стену или за границу сетки блокируется: агент остаётся на месте и платит
штраф за шаг. Это делает «упереться в стену» невыгодным без отдельного штрафа.

## Награды

| Событие | Значение | Частота | Завершает эпизод |
|---|---|---|---|
| шаг | −0.04 | каждый шаг | нет |
| достижение цели (4,4) | +1.0 | однократно | да (`terminated`) |
| попадание в ловушку (1,3) или (3,1) | −1.0 | однократно | да (`terminated`) |
| исчерпание `MaxStep` = 100 | — | однократно | да (`truncated`) |

**Оптимальная сумма наград — 0.68**: кратчайший путь занимает 8 шагов,
`1.0 − 8 × 0.04 = 0.68`. Число посчитано не на глаз, а Value Iteration на
модели MDP (`labrl.envs.gridworld_mdp`), и служит точным ориентиром для
чтения графиков: 0.68 — потолок, ниже −1 — систематическое попадание в ловушки.

## Эпизод

- **Старт:** фиксированная клетка (0,0) (`randomStart = false`).
- **Завершение (terminated):** цель или ловушка.
- **Обрыв (truncated):** `MaxStep` = 100.
- **Рандомизация:** отсутствует; `slipProbability = 0`.
- **Детерминизм:** полный. Среда без физики, поэтому при фиксированном сиде
  прогон воспроизводится побитово — редкий случай, обычно мешает недетерминизм PhysX.

## Арены

| Параметр | Значение |
|---|---|
| Prefab | `Prefabs/TrainingArea.prefab` |
| Число арен | 4 |
| Шаг размещения | 8 единиц по X |
| Изоляция | арена занимает 5 единиц, зазор 3; физики и рейкастов в среде нет вовсе — перемещение телепортом по индексу клетки |

Каждая арена получает **свой** генератор случайных чисел
(`TrainingAreaBase`, сид = базовый сид × 7919 + индекс арены), поэтому арены
не идут синхронно и прогон остаётся воспроизводимым.

## Результаты

| Алгоритм | Сидов | Eval/Mean Reward | Eval/Success Rate | Шагов | Время |
|---|---|---|---|---|---|
| `qlearning` | 3 (0, 1, 2) | **0.6800** на каждом | 100 % | 20 000 | ~70 с на сид |

Разброса между сидами нет: среда детерминирована, а табличный Q-learning на
25 состояниях сходится к оптимуму задолго до конца бюджета. Доверительный
интервал вырожден в точку, поэтому IQM здесь не информативен — он приводится
для единообразия в `docs/RESULTS.md`.

**Сверка с эталоном.** Жадная политика, выученная Q-learning, выбирает
оптимальное действие в **100 %** состояний — сверено с `Q*` из Value Iteration
(критерий `optimality_rate`, а не совпадение argmax: в сетке есть равноценные
действия, и требовать совпадения конкретного argmax значило бы проверять
случайность разрыва ничьих).

| Награда в Python (20 эпизодов) | 0.6800 |
| Награда в Unity (20 эпизодов) | **0.6800**, исходы: `Goal` × 20 |
| Отношение Unity / Python | **1.000** (порог приёмки 0.8) |

Как табличный метод вообще попал в ONNX. Таблица `Q` формы (25, 4)
оборачивается линейным слоем без смещения: при one-hot наблюдении
`onehot(s) @ Qᵀ == Q[s]`, то есть слой возвращает ровно строку таблицы.
В Unity уезжает **та же** политика, а не её аппроксимация; численный паритет
ONNX ↔ PyTorch равен нулю в точности (`max|Δ| = 0.000e+00`).

## Известные ограничения

- Старт фиксирован, поэтому оценка измеряет качество политики только на
  траектории из (0,0). Состояния вдали от этой траектории обучаются лишь
  благодаря ε-разведке; при `epsilon_end` ближе к нулю их покрытие ухудшится.
- `slipProbability` реализована, но в ТЗ выставлена в 0. Включение
  стохастичности переходов сделает среду ближе к FrozenLake и потребует
  пересчёта порога приёмки: 0.68 достижимо только в детерминированном случае.
- Четыре арены с фиксированным стартом дают коррелированный опыт: их траектории
  расходятся только за счёт ε-разведки.
