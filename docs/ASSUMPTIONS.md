# ASSUMPTIONS — Реестр допущений

Формат по `Claude Code Prompt Engineering Playbook v3.0`, п. 8.2.
Заполняется Claude Code. Каждое допущение — решение, принятое **без вопроса
пользователю**, потому что неопределённость некритична (правило 0.5 инструкции).
Блокирующая неопределённость в этот реестр не попадает — она выносится в вопросы
фазы (`PLAN.md`, раздел «Вопросы»).

| № | Допущение | Основание | Как изменить |
|---|---|---|---|
| A-1 | Имя Python-пакета — `labrl` | Задано инструкцией (Приложение C); конфликта с существующими пакетами PyPI нет | Указать другое имя, оформить ADR |
| A-2 | Один Unity-проект на все среды | Задано инструкцией 5.2; единый стек пакетов, общий `Shared/`, один `Library/` | Указать разделение по проектам, ADR |
| A-3 | Коды примеров `E##` двузначные | Задано инструкцией (Приложение C); до 100 примеров достаточно | Указать иную схему нумерации |
| A-4 | Порог инференса в Unity ≥ 0.8 от Python-оценки | Задано инструкцией 10.6; допуск на недетерминизм физики | Указать иной порог |
| A-5 | Батч Фазы 3 — 3 примера | Задано инструкцией 6/Фаза 3 | Указать иной размер батча |
| A-6 | Числовой паритет ONNX↔PyTorch (10.5) проверяется по выходам `deterministic_continuous_actions` / `deterministic_discrete_actions` | Выходы `continuous_actions` и `discrete_actions` стохастичны (`sample()`, `multinomial`), поэлементное сравнение по ним бессмысленно; детерминированные выходы описаны тем же графом и покрывают ту же цепочку вычислений | Указать иную процедуру сверки (например, фиксацию seed внутри графа) |
| A-7 | Вход рекуррентной памяти в контракте ONNX называется `recurrent_in`, а не `memory_in` | Фактическое имя в `TensorNames` и Python, и C# (`release_23_tag`); п. 16.4 отдаёт приоритет исходникам над текстом инструкции 10.3 | Не изменяется — определяется пакетом |
| A-8 | Контракт ONNX в Фазе 0 извлечён из исходников `release_23_tag` на GitHub, а не из установленного пакета | Пакет `mlagents` на машине отсутствует (блокер B-2), а установка пакетов до завершения Фазы 0 запрещена п. 0.3 | Снимается автоматически в Фазе 1: контракт пересверяется с установленным пакетом, статус `DRAFT` снимается |
| A-9 | Нумерация примеров в `docs/02_LESSON_MAP.md` (`E00`…`E11`) — предложение, а не решение | Инструкция 5.3 запрещает менять код после присвоения, поэтому присвоение фиксируется только после подтверждения пользователем | Подтвердить или изменить в ответе на вопрос Q2 |
| A-10 | Уроки 1.1, 1.2, 2.5, 2.6, 3.5, 3.7, 3.8 получают статус `CROSS`, а не `MISSING_EXAMPLE` | Это теоретические, установочные и сквозные уроки; определение примера (1.2 инструкции) к ним неприменимо — они реализуются как свойства платформы | Указать, что для них нужны отдельные примеры |
| A-11 | Рабочая ветка создана как `feature/lab-bootstrap` от `main` без коммита-снимка | Требование 3.3; коммит-снимок (3.5) обязателен **перед первым изменением структуры**, то есть в начале Фазы 1, а Фаза 0 структуру не меняет | — |
